# OSAI Brainstorming

## Workflow

1. Ground ideas in the current OSAI roadmap, target audience, and stack before suggesting options.
2. Separate product intent from implementation detail. Clarify the user goal, audience, and success criteria when they are blurry.
3. Offer a small set of distinct options with tradeoffs, not a long undifferentiated idea list.
4. Recommend one direction when enough context exists, and explain the reason briefly.
5. Convert chosen ideas into next-step tasks that fit the existing phases in `AGENTS.md`.

## OSAI Product Lens

- Target young clothing shoppers with fast browsing, clear style discovery, and a low-friction cart/checkout.
- Favor practical ecommerce flows before advanced features.
- Keep Stripe, auth, database, and admin ideas sequenced after the simpler mocked/order flow where appropriate.
- Treat admin tooling as operational and efficient, not decorative.
- Validate feature ideas against implementation cost, user value, risk, and testability.

## Useful Outputs

- Feature option sets with pros, cons, and recommendation.
- Roadmap refinements that fit existing phases.
- UX flow concepts for browsing, cart, checkout, auth, and admin.
- Naming and positioning ideas for OSAI.
- MVP vs later-scope breakdowns.
